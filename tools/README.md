# tools

Служебные проверки и скрипты. В APK ничего отсюда не попадает, приложению они не нужны — только
сборке, проверкам перед пушем и тебе.

## Обход экранов на телефоне (`device_smoke`)

`device_smoke.ps1` — для Windows, `device_smoke.sh` — для Linux и macOS. Это близнецы: один и тот
же обход, записанный дважды под разные языки. **Перепутать их легко, и ошибка выглядит пугающе:**
если скормить PowerShell файл `.sh`, он выдаст полсотни строк про скобки и «отсутствует
закрывающий знак», потому что это не его язык. Поэтому у каждого файла в первой строке написано,
кто он. Проверка занимает секунду:

```
Get-Content "$env:USERPROFILE\device_smoke.ps1" -TotalCount 1
# должно быть: # device_smoke.ps1 - the Windows one. ...
```

### Windows

Скачать одной строкой (ссылка ведет прямо на файл в ветке; кнопка Raw на странице файла даёт то же
самое):

```
iwr -UseBasicParsing https://raw.githubusercontent.com/tommynok/FreezeYou/arena/01a0feb4-freezeyou/tools/device_smoke.ps1 -OutFile "$env:USERPROFILE\device_smoke.ps1"
```

Проверить, что не открывает ничего и никого не трогает (адб и телефон не нужны):

```
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\device_smoke.ps1" -ListOnly
```

Запустить обход — правым кликом по файлу («Выполнить с помощью PowerShell») или строкой:

```
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\device_smoke.ps1"
```

### Linux и macOS

```
tools/device_smoke.sh --list      # что будет открыто, ничего не делая
tools/device_smoke.sh             # обход
tools/device_smoke.sh --no-su     # не пользоваться root даже если он есть
```

### Что делает и чего не делает

Открывает 16 экранов по одному, снимает скриншот каждого, проверяет, что экран действительно
оказался на экране (а не открылся и сразу закрылся), возвращается назад и читает лог на краши и
`InflateException`. **Ничего не нажимает** — поэтому безопасен и на сборке с root.

Один из шестнадцати, «Папка ярлыков», без своего intent не показывает ничего: он строит разметку и
сразу закрывается — так он и написан (нет `UUID` — сообщение и `finish()`). Скрипт это знает и
печатает его отдельной строкой, а не как недостигнутый экран: на телефоне с root нормальный итог —
**«Covered 15 screen(s) of 16»**. Скриншот снимается только тогда, когда экран действительно сверху:
снимок «поверх» чужого экрана показывал бы не то, что написано на файле.

Тринадцать из этих шестнадцати экранов объявлены неэкспортированными: обычный `adb shell am start`
их не открывает. Если телефон согласен дать root оболочке adb, скрипт дооткрывает их через
`su -c` — root нужен только чтобы начать экран, нажатий и правок по-прежнему нет. Без root скрипт
перечисляет недостигнутые экраны и выходит с кодом 2: молчаливое «в логе чисто» на трёх
открытых экранах из шестнадцати было ошибкой первой версии.

Коды возврата: `0` — лог чистый и все экраны либо открылись, либо закрылись сами по устройству,
`1` — в логе краш или ошибка инфляции, `2` — лог чистый, но часть экранов не открылась,
`3` — нет adb или телефона, `4` — список экранов сломан (дубль или экран переименовали в
манифесте).

Monkey (случайные тапы) включается только явно и после предупреждения:

```
tools/device_smoke.sh --monkey 500
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\device_smoke.ps1" -Monkey 500
```

Приложение держит root и Shizuku, поэтому случайный тап может заморозить выбранные пакеты или
подтвердить удаление заданий. Перед прогоном лучше снять повышенные права или взять запасной
аппарат. В скрипте есть предупреждение и подтверждение словом `yes`; системные кнопки и переходы в
другие приложения из событий исключены.

## Проверки перед пушем

Идут без телефона и без Gradle, разбором файлов:

- `check_theme_resolution.py` — чем обернется каждый стиль на API 19/21/29/31/34: перекрытие
  базового стиля в `values-vNN`, родитель AppCompat у тёмной темы, потерянный
  `colorSurface`/`colorPrimary`/`actionBarPopupTheme`.
- `check_layout_variants.py` — разметка, разложенная на `layout/` и `layout-vNN/`, где обновили
  только одну копию.
- `check_settings_keys.py` — `app:key` каждой настройки против имён ключей в `storage/key`.

Все три — отчёты: печатают найденное и выходят с нулем. `check_theme_resolution.py` понимает
`--strict`, если понадобится валить сборку.
