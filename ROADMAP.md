# Роадмап форка

Личный список форка `tommynok/FreezeYou`. Не относится к апстриму.

Стабильная точка отката: ветка `stable-2026-08-13` (коммит `89d485c`, сборка Actions #76).

## Тесты

Запускаются на JVM командой `./gradlew testReleaseUnitTest`, без телефона и эмулятора.
В CI выполняются перед сборкой, занимают секунды. В APK не попадают.

Покрыто:

- `ShortcutTargetTest` — цель ярлыка: «Запуск» → пусто, «Только разморозить» →
  `@onlyUnfreeze`, имя класса остаётся как есть, ярлык переживает смену языка. Именно
  здесь ярлыки и ломались.
- `SearchRankingTest` — порядок результатов поиска: совпадение по началу названия, потом
  по вхождению в название, потом по имени пакета.

Ещё не покрыто, требует `Robolectric` или подмены SQLite:

- `TasksUtils.collectTriggeredTasks` — отбор по триггеру, пустой `tgextra` = «любое
  приложение», подстановка `[cpkgn]`, батч-вариант со списком пакетов.
- `OneKeyListUtils.decodeUserListsInPackageNames` — тут был баг с пустым именем пакета.
- `CriticalPackagesUtils.findCriticalPackages` — подтверждение при заморозке важных
  системных пакетов.
- `tools/check_layout_variants.py` — у самого скрипта проверок тоже нет.

Заморозку через Shizuku автотестами не покрыть — нужен реальный аппарат.

## Ручная проверка после правок по скорости — пройдена

Одиночные действия из главного списка переведены в свой процесс, затронуты были все режимы
нажатия на строку. Проверено на устройстве:

- [x] «Заморозить немедленно» и «Разморозить немедленно»
- [x] «Разморозить и запустить» — и с промежуточным вопросом, и сразу
- [x] Заморозка приложения с уведомлением — защита срабатывает (была сломана переносом
      в другой процесс, чинилось общим состоянием через многопроцессный MMKV)
- [x] Заморозка приложения переднего плана — через запланированное задание
- [ ] «Авто заморозка/разморозка» — не проверялась, режим не используется

Защита «не морозить приложение переднего плана» при тапе по списку сработать не может по
смыслу: в этот момент на переднем плане сама FreezeYou. Она рассчитана на заморозку без
участия пользователя — расписание, ярлыки, виджеты.

## Обесцвеченные значки замороженных приложений — сделано, нужна проверка на устройстве

Второй маркер заморозки в дополнение к точке в конце строки. Работает и в списке, и в сетке,
переключается настройкой «Обесцвечивать замороженные приложения» в разделе «Внешний вид»
(ключ `greyFrozenApplicationsIcons`, по умолчанию включено).

Раньше обесцвечивание было только в сетке и делалось через `getGrayBitmap`, то есть копией
каждого значка в ARGB_8888. Теперь на `ImageView` в `MainAppListSimpleAdapter.getView`
ставится общий `ColorMatrixColorFilter`: копий значков нет, при смене состояния значок не
пересоздаётся, а `Main` перестал дёргать `realGetFrozenStatus` лишний раз на каждое
приложение при построении списка. Кода стало меньше, чем было.

Подводные камни, на которые уже наступили в коде, ломать их обратно не надо:

- `getView` переиспользует view, а `setImageDrawable` фильтр не сбрасывает — поэтому фильтр
  снимается так же явно, как ставится.
- Настройка перечитывается в адаптер при каждом обновлении списка, а не только при создании:
  адаптер переживает поход в настройки и обратно.
- Флаг заморозки лежит в списке отдельным ключом `Frozen`, потому что `isFrozen` — это id
  ресурса точки, зависящий от темы.

Проверить на устройстве: список и сетка, переключатель в обе стороны, прокрутка длинного
списка (не «поедет» ли серость по чужим строкам), заморозка и разморозка одиночная и пакетная.

## Отложено

- **Отмена после массовой операции.** Низкий приоритет. Фильтры «замороженные» есть, но не
  по дате, так что откатить последнюю пачку нечем.
- **Остальные разделы офлайн-справки** — 7, 7.1, 7.2. Сейчас переведён только синтаксис
  команд запланированных заданий, остальное вторично.
- **Закреплённая секция «Моя подборка» вверху главного списка.** Требует переработки
  адаптера списка, поэтому отдельной задачей.

## Идеи

- **Поиск по настройкам.** Настроек много, и найти нужную можно только пролистав все разделы.
  Поиск по заголовкам и описаниям пунктов давно стал нормой.
- *(сделано)* Обесцвеченные значки замороженных приложений — см. ниже.

## Известные слабые места

- Цель ярлыка «Запуск» хранится как отсутствие значения, а не как явный маркер. Работает,
  но менее явно, чем `@onlyUnfreeze` рядом.
